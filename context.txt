1. PROJECT OVERVIEW
--------------------------------------------------------------------------------

A full-stack distributed job queue manager. Users log in via OAuth (Google /
GitHub), create Projects, define Queues inside those projects, and enqueue Jobs.
A Spring Boot worker process polls queues, executes jobs, handles retries, and
manages a dead-letter queue for exhausted jobs.

Tech stack:
  - Backend  : Java 21, Spring Boot 3.3.2, Spring Security, Spring Data JPA
  - Database : Supabase-hosted PostgreSQL (transaction pooler, ap-southeast-1)
  - Auth     : Supabase Auth (OAuth — Google + GitHub), JWT (ES256 / ECDSA P-256)
  - Frontend : React 18, TypeScript, Vite, React Router v6, Supabase JS SDK, Axios
  - Build    : Maven (backend), npm / Vite (frontend)

3. DATABASE SCHEMA  (database/schema.sql)
--------------------------------------------------------------------------------

Tables:
  users                 — id (UUID = Supabase auth.users.id), email, name, avatar_url
  organizations         — id, name, slug
  organization_members  — user_id + org_id composite PK, role
  projects              — id, user_id (FK→users), org_id (FK→organizations), name, api_key_prefix
  queues                — id, project_id (FK→projects), name, concurrency_limit (default 5),
                          is_paused (default false), default_retry_config (JSONB)
  workers               — id, name (UNIQUE), last_heartbeat_at, status (active|draining|offline)
  jobs                  — id, queue_id (FK→queues), status (pending|scheduled|claimed|running|
                          completed|failed|dead), priority (SMALLINT), scheduled_at,
                          next_retry_at, locked_at, locked_by, attempt_count, max_attempts,
                          retry_config (JSONB), payload (JSONB), last_error
  job_attempts          — id (BIGSERIAL), job_id, attempt_number, worker_name, started_at,
                          finished_at, error_stack
  dead_letter_entries   — id, job_id, original_payload (JSONB), error, died_at

Key indexes:
  idx_jobs_poller       — (queue_id, priority DESC, scheduled_at) WHERE status IN (pending, scheduled)
  idx_jobs_reaper       — (status, locked_at) WHERE status = claimed
  idx_queues_project_name — UNIQUE (project_id, name)
  idx_jobs_user_lookup  — (queue_id)
  idx_job_attempts_job_id — (job_id, started_at DESC)

Triggers:
  set_updated_at()      — auto-updates updated_at column on users, organizations, projects, jobs

Note: VARCHAR + CHECK constraints used instead of PG enum types for full
Hibernate @Enumerated(STRING) compatibility.

6. BACKEND — SERVICES  (backend/src/main/java/com/jobscheduler/service/)
--------------------------------------------------------------------------------

JobService.java
  - enqueue()        : creates Job with status=pending or scheduled depending on scheduledAt
  - listByQueue()    : paginated query, optional status filter
  - listByUser()     : paginated, cross-queue view for a user
  - get()            : fetch single job
  - getAttempts()    : fetch all JobAttempts for a job
  - claimJobs()      : SELECT FOR UPDATE SKIP LOCKED — atomically claims N jobs
  - markRunning()    : transitions claimed → running
  - completeJob()    : records attempt, sets status=completed
  - failJob()        : records attempt, applies retry logic or moves to dead
  - cancelJob()      : sets status=dead (not allowed on running/claimed)
  - requeueDeadJob() : resets dead/failed job back to pending with attempt_count=0
  - resetStuckJob()  : called by Reaper, resets stuck claimed jobs to pending
  - calculateNextRetry() : supports exponential (default, with jitter), linear, fixed strategies
  - effectiveMaxAttempts(): cascading priority — job retryConfig > queue defaultRetryConfig > job.maxAttempts
  - moveToDead()     : creates DeadLetterEntry when retries exhausted

ProjectService.java
  - listForUser(), getForUser(), create(), rename(), delete()
  - generateKeyPrefix() : generates "js_" + 8-char random hex prefix

QueueService.java
  - listForProject(), getForProject(), create(), update(), pause(), resume(), delete()
  - verifyOwnership() : checks project belongs to requesting user

10. BACKEND — BACKGROUND WORKERS  (backend/src/main/java/com/jobscheduler/worker/)
--------------------------------------------------------------------------------

CronScheduler.java
  - promoteScheduledJobs()  : every 10 s — flips scheduled→pending for jobs whose
                              scheduled_at has passed
  - heartbeat()             : every 15 s — upserts worker heartbeat into workers table
  - markOffline()           : @PreDestroy — marks worker offline on graceful shutdown

JobPoller.java
  - poll()                  : every 2 s — iterates all active (non-paused) queues,
                              respects per-queue Semaphore (concurrencyLimit permits)
  - executeAsync()          : @Async — marks job running, calls processJob(), then
                              completeJob() or failJob()
  - processJob()            : stub — simulates 100–500 ms work (replace with real dispatch)
  - Per-queue ConcurrentHashMap<UUID, Semaphore> prevents over-saturation

Reaper.java
  - reap()                  : every 60 s
    - reaperSweepJobs()     : finds claimed jobs locked > 5 min, resets to pending
    - reaperSweepWorkers()  : marks workers with no heartbeat in 60 s as offline

14. FRONTEND — HOOKS  (frontend/src/hooks/)
--------------------------------------------------------------------------------

useSupabaseAuth.ts
  - Central auth hook; wraps supabase.auth.getSession + onAuthStateChange
  - Returns: session, user (AuthUser shape), loading, signInWithGoogle,
    signInWithGitHub, signOut

usePolling.ts
  - Runs fn() immediately then on every intervalMs
  - Accepts enabled flag (pauses when false, e.g. session not ready)
  - Ref-based to always call latest closure

useSessionReady.ts
  - Returns boolean true once a valid Supabase session is confirmed
  - Used to gate API calls — prevents 401s on page load before token is available

21. KNOWN DESIGN DECISIONS
--------------------------------------------------------------------------------

- No Docker / deployment config exists yet.
- No tests written yet (test directory is empty).
- JobPoller.processJob() is a stub (Thread.sleep simulation). Real job dispatch
  should route by payload "type" to registered JobHandler beans.
- Organization model exists in schema/entities but is not wired into the API yet
  (no OrganizationController).
- api_key_prefix on Project is generated but no API-key-based auth path exists yet.
- Slug-based routing (projectName/queueName in URLs) resolved by fetching all
  items and doing client-side slug match — not passed as a query param to backend.
- CORS is applied to all paths (not just /api/**) so error responses (401, 500)
  also carry correct CORS headers.
